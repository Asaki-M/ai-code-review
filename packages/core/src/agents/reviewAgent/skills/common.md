# 通用 Code Review 规范

## 审查优先级
- 优先识别会导致线上事故、数据损坏、安全漏洞、权限绕过、兼容性破坏的问题。
- 区分阻塞问题和建议项，不要把纯风格偏好判定为必须修改。
- 对无法从 diff 确认的问题，标记为风险或需确认，不要臆造上下文。

## 正确性
- 检查边界条件、空值处理、异常路径、并发竞争、幂等性和回滚逻辑。
- 检查新增逻辑是否破坏旧行为、公共 API、配置默认值或数据格式。
- 检查时间、时区、排序、分页、金额、精度、编码和国际化处理。

## 可维护性
- 关注重复逻辑、过度抽象、命名不清、职责混杂和不可测试代码。
- 优先建议最小可行修复，避免引入和问题不匹配的大重构。
- 对复杂逻辑建议补充测试、日志或注释，但不要要求无意义注释。

## 测试
- 检查是否覆盖关键分支、失败路径、边界输入和回归场景。
- 对缺失测试的问题说明具体应该覆盖什么，不要笼统说“需要测试”。
